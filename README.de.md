## Warum ~80 Tokens?

Die meisten AI-Coding-Werkzeuge packen 15.000–28.000 Tokens in jede Anfrage — Regeln, Tool-Definitionen, Rollen-Prompts, Formatierungsanweisungen. Die AI verbringt den Großteil ihrer Aufmerksamkeit mit dem Lesen von Standardtexten, anstatt Ihr Problem zu lösen.

Huiyu Pi verfolgt den gegenteiligen Ansatz: Alles Unnötige wird entfernt. 4 grundlegende Tools. Saubere Arbeitsfläche. Kein Ballast.

| | Vorher (typisch) | Huiyu Pi |
|---|---|---|
| System-Prompt-Overhead | 15K–28K Tokens | **~80 Tokens** |
| Antwortzeit erstes Token | 2–10 Sekunden | **~0.3 Sekunden** |
| Kosten pro Anfrage | $0.02–$0.10+ | **90%+ günstiger** |
| Tool-Definitionen | 10–24+ | **4 wesentliche** |
| Client-Typ | Schweres Desktop / Electron | **Reines Web-UI** |
| Datenschutz | Cloud oder Hybrid | **100% lokal** |

## Warum Huiyu Pi wählen?

Aufgebaut auf pi und pi-forge, mit Behebung des fehlenden Frontend-WebUI und der umständlichen Interaktionsdetails. Huiyu Pi ist ein browserbasiertes WebUI für den pi-Coding-Agent — es ist unglaublich schnell und macht einfach Spaß — deshalb teile ich es.

| | Vorteil | Details |
|---|---|---|
| ⚡ | **Schnellere Leistung** | Standard-Kontext und Prompts von ~20K Tokens auf nahe null komprimiert. Die AI-Antwortzeit ist drastisch kürzer. |
| 💰 | **Geringerer Token-Verbrauch** | Der meiste ungenutzte Kontext wird entfernt, wodurch die API-Kosten pro Anfrage drastisch sinken. |
| 🎯 | **Weniger Kontext, mehr Fokus** | Weniger Kontext = Die AI bleibt auf die Kernanweisungen fokussiert für präzisere Ausführung. |
| 🔒 | **Lokale Deployment = Sicher** | Vollständig lokal — API-Schlüssel und Daten verlassen niemals Ihren Computer. Kein Risiko von Datenlecks. |
| 🏗️ | **Bauen Sie Ihr AI-Imperium** | Bauen Sie Ihr eigenes Harness und Agent von Grund auf. Volle Kontrolle, vollständig anpassbar. |
| 🛠️ | **Behebung der Lücken des Originals** | Behebt pis fehlendes WebUI und pi-forges Interaktionsprobleme. Unglaublich schnell, extrem flüssig. |

## Schnellstart

```bash
npx huiyu-pi
```

Öffnen Sie `http://localhost:9144` in Ihrem Browser, gehen Sie zu **Einstellungen → Anbieter**, geben Sie Ihren API-Schlüssel ein und starten Sie das Gespräch.

*Auch verfügbar als globale npm-Installation, manuelles Klonen oder Plattform-Skripte — siehe [Installation](#installation) unten.*

## Funktionen

### 🔐 Selbst gehostet & Privat
Ihr Code, Ihre API-Schlüssel und Ihre Gesprächsverlauf bleiben auf Ihrem eigenen Computer. Keine Cloud, kein Drittanbieter, keine Datenleckage.

### 🧠 Multi-LLM-Unterstützung
Funktioniert mit Anthropic Claude, OpenAI GPT/o1/o3, DeepSeek, Google Gemini, Mistral, Groq, xAI, OpenRouter und mehr — einschließlich lokaler Modelle.

### 🁂 Vollständiges Dateimanagement
Integrierter Dateibrowser mit CodeMirror-Editor und Unterstützung für über 10 Sprachen. Dateien direkt im Browser erstellen, bearbeiten und durchsuchen.

### 🖥️ Integriertes Terminal
Vollständiger Terminal-Emulator über xterm.js + WebSocket. Mehrere Tabs, Wiederverbindungsunterstützung, anpassbares Layout.

### 🔀 Git-Integration
Diffs anzeigen, Änderungen auf Hunk-Ebene indexieren, Commit-Verlauf mit git-graph erkunden — alles im Browser.

### 🔌 MCP-Protokoll-Unterstützung
Externe MCP-Server verbinden und deren Tools Ihrem Coding-Agent zugänglich Unterstützt sowohl globale als auch projektspezifische Konfigurationen.

### 📱 Mobilfreundlich + PWA
Responsives Design funktioniert auf iOS/Android. Als PWA installieren für eine native-ähnliche Erfahrung.

### 🎨 Vollständig anpassbares Design
Dunkle und helle Themes, gesteuert durch CSS-Variablen. Erstellen Sie Ihr eigenes Theme ohne Neukompilierung.

## Installation

**Voraussetzungen:** Node.js ≥ 20 ([herunterladen](https://nodejs.org/)). Build-Tools werden für die Terminal-Unterstützung benötigt: Installieren Sie [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) (Windows), `xcode-select --install` (macOS) oder `build-essential` (Linux). Der Chat und der Dateibrowser funktionieren ohne Build-Tools — nur der Terminal-Tab benötigt sie.

### Option A: npx (keine Installation, einmaliger Aufruf)

```bash
npx huiyu-pi
```

Lädt die neueste Version herunter und führt sie aus. Nachfolgende `npx huiyu-pi`-Aufrufe verwenden die zwischengespeicherte Version. Um ein erzwungenes Update durchzuführen: `npx huiyu-pi@latest`.

### Option B: Globale Installation (schnellere nachfolgende Starts)

```bash
npm install -g huiyu-pi
huiyu-pi                    # Server starten
huiyu-pi --help             # Alle Optionen anzeigen
huiyu-pi --port 4000        # Benutzerdefinierter Port
huiyu-pi --workspace-path ~/Code  # Benutzerdefinierter Arbeitsbereich
```

Zum Aktualisieren: `npm update -g huiyu-pi`. Zum Deinstallieren: `npm uninstall -g huiyu-pi`.

### Option C: Plattform-Skripte (Klonen + Ausführen)

Klonen Sie das Repository und führen Sie das Startskript für Ihre Plattform aus:

| Plattform | Befehl |
|---|---|
| **Windows** | Doppelklick auf `start.bat` oder in PowerShell ausführen: `.\start.bat` |
| **macOS / Linux** | Terminal öffnen, `cd` in das Repository, dann `bash start.sh` |

Das Startskript erledigt alles: `npm install` → Server erstellen → Client erstellen → Starten. Der erste Start dauert einige Minuten; nachfolgende Starts sind schnell.

**LAN-Zugang** (Freigabe in Ihrem lokalen Netzwerk):

| Plattform | Befehl |
|---|---|
| **Windows** | `.\start-lan.bat` |
| **macOS / Linux** | `bash start-lan.sh` |

Oder über Option: `huiyu-pi --host 0.0.0.0`

> ⚠️ **Sicherheit:** Das Binden an `0.0.0.0` stellt die Shell und das Dateisystem des Agents für **alle Personen in Ihrem Netzwerk** bereit. Verwenden Sie dies nur in vertrauenswürdigen privaten Netzwerken.

### Option D: Manuell (Entwicklung)

```bash
git clone https://github.com/huiyu9144/Huiyu-Pi.git
cd Huiyu-Pi
npm install          # Alle Abhängigkeiten installieren (erstmalig kann einige Minuten dauern)
npm run dev          # Dev-Server mit HMR starten (http://localhost:9145)
```

Für Produktions-Builds:

```bash
npm run build        # Server + Client erstellen
npm run start        # Produktions-Server auf Port 9144 starten
```

### Option E: Docker (empfohlen für Produktion)

**Aus der Registry ziehen** (kein Klonen nötig):
```bash
docker run -d \
  --name huiyu-pi \
  -p 9144:9144 \
  -v ~/.pi/agent:/home/pi/.pi/agent \
  -v ~/.huiyu-pi:/home/pi/.huiyu-pi \
  -v $(pwd)/workspace:/workspace \
  ghcr.io/huiyu9144/huiyu-pi:latest
```

**Oder lokal erstellen** (für Anpassungen):
```bash
git clone https://github.com/huiyu9144/Huiyu-Pi.git
cd Huiyu-Pi/docker
cp .env.example .env
docker compose up -d --build
```

Öffnen Sie `http://localhost:9144` in Ihrem Browser.

**Benutzerdefinierte UID/GID** (Berechtigungsprobleme bei Bind-Mounts beheben):
```bash
docker compose build --build-arg PUID=$(id -u) --build-arg PGID=$(id -g)
docker compose up -d
```

Für detaillierte Docker-Konfiguration siehe [docker/README.md](docker/README.md).

## API-Schlüssel-Einrichtung

Huiyu Pi verwaltet die API-Schlüssel der Anbieter über die **Einstellungen-Oberfläche** und speichert sie in `~/.pi/agent/auth.json` (gemeinsam mit der `pi`-CLI, falls installiert). Schlüssel werden niemals an den Browser weitergegeben — der Server hält sie im Speicher und leitet alle LLM-Anfragen weiter.

### Über die Einstellungen-Oberfläche (Empfohlen)

1. Öffnen Sie `http://localhost:9144`
2. Gehen Sie zu **Einstellungen → Anbieter**
3. Wählen Sie Ihren Anbieter (Anthropic, OpenAI, DeepSeek usw.)
4. Fügen Sie Ihren API-Schlüssel ein und speichern Sie

### Unterstützte Anbieter

Anthropic Claude, OpenAI GPT/o1/o3, DeepSeek, Google Gemini, Mistral, Groq, xAI, OpenRouter und jeder OpenAI-kompatible Endpunkt (vLLM, LiteLLM, Ollama usw.).

### Benutzerdefinierte OpenAI-kompatible Anbieter

Für selbst gehostete oder Drittanbieter-Endpunkte erstellen Sie `~/.pi/agent/models.json`:

```json
{
  "custom-gateway": {
    "protocol": "openai",
    "url": "http://localhost:11434/v1",
    "models": ["qwen2.5-coder-32b"]
  }
}
```

Fügen Sie dann den API-Schlüssel in **Einstellungen → Anbieter → custom-gateway** hinzu.

### CLI-Option (für Skripte / CI)

```bash
huiyu-pi --api-key @/path/to/api-key.txt
```

Das `@`-Präfix liest den Schlüssel aus einer Datei. Nützlich für CI-Pipelines und Docker-Geheimnisse.

## Konfiguration

Alle Einstellungen können über CLI-Optionen, Umgebungsvariablen oder Konfigurationsdateien gesteuert werden. CLI-Optionen haben Vorrang vor Umgebungsvariablen, die wiederum Vorrang vor Konfigurationsdateien haben.

### CLI-Optionen

| Option | Beschreibung | Standardwert |
|---|---|---|
| `--port` | Server-Port | `9144` |
| `--host` | Bindeadresse | `127.0.0.1` |
| `--workspace-path` | Stammverzeichnis für Projekte | `~/huiyu-pi-workspace` |
| `--api-key` | Statischer API-Schlüssel (`@file`-Syntax unterstützt) | — |
| `--ui-password` | Browser-Anmeldekennwort | — |
| `--jwt-secret` | JWT-Signaturschlüssel (wenn nicht gesetzt, automatisch generiert) | — |
| `--log-level` | Log-Level: `fatal` `error` `warn` `info` `debug` `trace` | `info` |
| `--no-expose-docs` | Swagger UI im Browser ausblenden | Docs sichtbar |
| `--help` | Alle Optionen anzeigen | — |

### Umgebungsvariablen

| Variable | Beschreibung |
|---|---|
| `PORT` | Server-Port |
| `HOST` | Bindeadresse (`0.0.0.0` für LAN) |
| `WORKSPACE_PATH` | Stammverzeichnis für Projekte |
| `API_KEY` | Statischer API-Schlüssel |
| `UI_PASSWORD` | Browser-Anmeldekennwort |
| `JWT_SECRET` | JWT-Signaturschlüssel |
| `LOG_LEVEL` | Log-Level |
| `EXPOSE_DOCS` | Auf `false` setzen, um Swagger UI auszublenden |
| `FORGE_DATA_DIR` | Status-Verzeichnis überschreiben (Standard: `~/.huiyu-pi/`) |

### Konfigurationsdateien

| Datei | Zweck |
|---|---|
| `~/.pi/agent/auth.json` | Anbieter-API-Schlüssel (verwaltet über die Einstellungen-Oberfläche) |
| `~/.pi/agent/settings.json` | Agent-Einstellungen (Modell, Denklevel usw.) |
| `~/.pi/agent/models.json` | Benutzerdefinierte OpenAI-kompatible Anbieter |
| `~/.huiyu-pi/mcp.json` | Globale MCP-Server-Konfiguration |
